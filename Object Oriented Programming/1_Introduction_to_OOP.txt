INTRODUCTION TO OBJECT ORIENTED PROGRAMMING (OOP)
====================================================

--------------------------------
1. WHAT IS OOP AND WHY IT EXISTS
--------------------------------

OOP stands for Object Oriented Programming.

It is a way of writing code where we organize our program around
"objects" instead of just functions and logic.

An object is simply a thing that has:
    - Properties (also called attributes) -> what it HAS
    - Behaviors (also called methods)      -> what it CAN DO

For example, think of a real-world "Dog":
    Properties : name, breed, color, age
    Behaviors  : bark(), eat(), sleep(), run()

In code, we can group all of this together inside something called
a "class", and then create objects (real dogs) from that class.

WHY DOES OOP EXIST?

As programs grow bigger, plain step-by-step code (procedural code)
becomes messy, repetitive, and hard to manage. OOP was introduced to:

    1. Keep related data and functions together in one place
    2. Make code reusable (write once, use many times)
    3. Make code easier to understand, maintain, and extend
    4. Model real-world things more naturally in code
    5. Reduce code duplication using inheritance (explained later)

In short: OOP helps us write code that is organized, reusable,
and closer to how we think about real-world things.


--------------------------------------------
2. PROCEDURAL vs OBJECT-ORIENTED PROGRAMMING
--------------------------------------------

PROCEDURAL PROGRAMMING:
    - Code is written as a series of steps / functions
    - Data and functions are separate
    - Works fine for small, simple programs
    - Becomes harder to manage as the program grows

OBJECT-ORIENTED PROGRAMMING:
    - Code is organized around objects
    - Data (properties) and functions (behaviors) are bundled together
    - Easier to reuse, extend, and maintain for larger programs

SIMPLE COMPARISON EXAMPLE:

Imagine we want to store and display information about a student.

--- Procedural Style (without OOP) ---

    student_name = "Ali"
    student_age  = 20

    def display_student(name, age):
        print(name, age)

    display_student(student_name, student_age)

Here, the data (student_name, student_age) and the function
(display_student) are completely separate. If we had 100 students,
we would need 100 sets of separate variables, or messy lists.

--- Object-Oriented Style (with OOP) ---

    class Student:
        def __init__(self, name, age):
            self.name = name
            self.age = age

        def display_student(self):
            print(self.name, self.age)

    student1 = Student("Ali", 20)
    student1.display_student()

Here, the data AND the function that works on that data are bundled
together inside one "Student" class. Now we can easily create as
many students as we want, and each one manages its own data cleanly.

(Don't worry about understanding every line above yet -- classes,
objects, and "self" will be explained in detail in the next files.
This is just to give you the general idea.)


--------------------------------
3. FOUR PILLARS OF OOP
--------------------------------

OOP is built on four main concepts. We will study each one in detail
later in this folder, but here are simple definitions to get started:

1. ENCAPSULATION
   Wrapping data and the methods that work on that data together
   inside one unit (a class), and protecting that data from
   unwanted outside access.

2. ABSTRACTION
   Hiding complex internal details and showing only the necessary,
   simple parts to the user.

3. INHERITANCE
   Allowing one class to reuse the properties and behaviors of
   another class, instead of writing the same code again.

4. POLYMORPHISM
   Allowing the same function or method name to behave differently
   depending on the object that is using it.

(Just remember these definitions for now. Each one will get its own
dedicated file later in this folder with full explanations and
examples.)


--------------------------------
4. REAL-WORLD ANALOGY: A "CAR"
--------------------------------

Let's understand OOP using a real-world object: a CAR.

A car has:

    PROPERTIES (what it HAS):
        - color
        - brand
        - model
        - speed
        - fuel level

    BEHAVIORS (what it CAN DO):
        - start()
        - accelerate()
        - brake()
        - stop()

In OOP, we would create a "Car" class that defines these properties
and behaviors. Then, every actual car (Toyota, Honda, Suzuki) becomes
an OBJECT created from that same "Car" class -- each with its own
specific values for color, brand, speed, etc., but all sharing the
same behaviors defined in the class.

This is the core idea of OOP:
    CLASS  = the blueprint/design (e.g., "Car" blueprint)
    OBJECT = the actual thing built from that blueprint (e.g., your car)


--------------------------------------
5. WHY PYTHON IS GREAT FOR LEARNING OOP
--------------------------------------

Python is one of the best languages to learn OOP because:

    1. Simple, clean, and readable syntax -- less boilerplate code
       compared to languages like Java or C++
    2. Everything in Python is actually an object internally,
       which makes OOP concepts feel natural
    3. No need to worry about complex setup (compilers, strict typing)
    4. Great for beginners while still being powerful enough for
       real-world, large-scale applications
    5. Widely used in the industry, so learning OOP in Python is a
       skill that is directly useful in real jobs
